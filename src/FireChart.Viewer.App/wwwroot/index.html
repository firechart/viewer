What it does

  • Any FHIR® server. The resource types the server has, lists with FHIR® search, each resource as a readable card or as its source in JSON or XML, the references between them. STU3, R4, R4B, R5 and R6.
  • The summary of a patient. Problems, medications, allergies, results with their trends, encounters and more on one page.
  • Search forms. Generated from the search parameters of the FHIR® release, with the codes from the terminology of the server and references found as you type.
  • Bundle Visualizer. A Bundle as the graph of the references between its resources: a document, a transaction, the result of $everything. Tap a resource for its card and its source.
  • SMART on FHIR. Sign-in with PKCE, by redirect or in a popup, so a protected server opens as well as an open one.
  • Your look. Light and dark themes, your colours and fonts. English, German, Spanish, Hebrew, Russian and Chinese. The forms of the records are XML components you can replace.

Where the data goes

The Viewer is static files. It runs in the browser as WebAssembly and talks to the FHIR® server directly: patient data and access tokens never pass through a server of the Viewer or of the page that embeds it, and the Viewer keeps no database. It only reads and never writes to the FHIR® server.

Use it in your application

Run the Docker image ghcr.io/firechart/viewer (linux/amd64 and linux/arm64) or copy the published files to any static web server, then put the Viewer into your page with an <iframe> or with the JavaScript SDK. The SDK is one ES module with TypeScript types: it creates the frame, passes the configuration and turns the messages of the frame into events and promises. Blazor applications can render the component <FhirViewer> directly.

Questions

Where does the patient data go?

Nowhere but the browser. The Viewer runs in the browser as WebAssembly and talks to the FHIR® server directly. The data and the access tokens never pass through a server of the Viewer or of the page that embeds it.

Which FHIR® servers does it work with?

Any FHIR® server of the releases STU3, R4, R4B, R5 or R6 that allows the origin of the Viewer (CORS). Open servers work at once, and a server that needs a sign-in is opened with SMART on FHIR.

How do I put it into my application?

Serve the Viewer with its Docker image or copy its files to any static web server, then embed it with an iframe or with the JavaScript SDK, one ES module without dependencies. There are examples for plain HTML, React, Angular and Vue.
