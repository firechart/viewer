# Assets/Styles

These files are the **sources of the Tailwind build**, not stylesheets the browser loads.

`Lombiq.Tailwind.Targets` compiles `site.css` (with its `@import`s: `tokens.css`, `palette.css`,
`components.css`) on every build into `wwwroot/css/Flox.Shared.Tailwind.css`. Only that output is
served. The paths are set in `Flox.Shared.csproj`; `Assets/Styles/site.css` is the package's default input.

Why the sources are not in `wwwroot`:

- Everything in `wwwroot` becomes a static web asset: it is published, shipped to the WASM client and
  the Docker image, and served by URL. The raw files hold `@theme`, `@source` and `@apply`, which a
  browser does not understand, so they would only be dead weight.
- The package scans the `.css` files next to the input. Keeping the input apart from the output keeps
  the generated file out of its own sources.
- Source and artifact stay apart: edit the files here, never `wwwroot/css/*.Tailwind.css`
  (it is regenerated by the build).

Plain CSS that needs no Tailwind build (e.g. `wwwroot/app.css`) lives directly in `wwwroot`.
